## 범위

기본 정보(템플릿·VM 이름·VMID), 배치·사양, 네트워크·접속, 최종 검토로 나눈다. 이전 단계 입력은 유지하고 수정 시 이전 검토·승인·동의를 무효화한다. 작업 ID는 자동 생성해 상세 정보로 내린다. 생성 요청 뒤 기존 Operation 화면으로 이동한다.

VMID 추천용 읽기 API와 선택적 `vmid`·`vm_name` 입력을 추가한다. 미지정 기존 API 호출은 자동 선택을 유지한다. UI는 추천값을 입력란에 표시하고 수정할 수 있다. 검토와 실행 직전 Proxmox 기반 중복 검증·승인 plan의 정확한 VMID·기존 durable lock을 유지한다. 추천은 예약이 아니고 충돌 시 재검토한다.

## 선택과 검증

한 화면의 접기보다 4단계를 채택한다. 이동 횟수는 늘지만 현재 결정할 항목에 집중할 수 있다. DB schema·권한·잠금 구조는 변경하지 않는다. 입력 이력 보존 정책도 유지한다.

1. 선택적 입력·추천 API 구현과 범위/형식/중복/승인 VMID 보존 테스트.
2. 단계별 UI와 이전 이동·수정·검토 무효화, DHCP 조건부 필드 구현. 비동기 작업 중 입력 변경 차단.
3. 프런트 테스트·lint·build, backend 전체 및 독립 quality-review. 실제 화면에서 단계 이동·입력 유지·검토를 확인한다.
4. API·생성 흐름 문서를 맞추고 완료 계획을 보관한다.

이 승인은 단계별 UI와 VMID·이름 입력 계약 구현·검증을 의미하며 실제 Proxmox VM 생성·운영 데이터 삭제를 의미하지 않는다. 실패 시 변경한 UI·선택적 입력 경로를 되돌릴 수 있다. 승인 대상이 변하거나 입력 변경 뒤 기존 승인이 유효하면 완료하지 않는다.
