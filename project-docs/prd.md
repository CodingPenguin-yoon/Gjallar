# Gjallar PRD

- 상태: `APPROVED` — 제품 방향. 개별 확장 기능의 구현·배포 완료를 뜻하지 않는다.
- 합의일: `2026-09-16`
- 방향 갱신일: `2026-09-25` — 빠른 완성을 위해 웹에 집중. 사용자 CLI·TUI 제거, 설치·서비스 관리 명령만 유지
- 현재 구현: [아키텍처](architecture.md)
- 순서와 진행 상태: [로드맵](roadmap.md)

## 1. 핵심 가치

**Proxmox 운영에 필요한 일을 갈랴르 한곳에서 쉽게 끝낸다.**

사용자는 갈랴르의 웹에서 템플릿을 준비하고 VM을 만들고 관리하며, 상태를 살피고 문제를 해결한다. 일상 업무를 처리하려고 Proxmox 관리 화면을 반복해서 오가지 않는 것이 목표다. 실제 자원 상태와 저수준 실행은 Proxmox가 담당하며 비상 관리 경로도 유지한다.

## 2. 누구를 위한 제품인가

첫 대상은 자신의 Proxmox 환경을 운영하는 개인과 소규모 인프라팀이다. 설치·연결·기본 운영을 탄탄하게 만드는 데 집중한다. 기업용 조직·결재·규제 준수 기능과 AI를 초기 제품의 전제 조건으로 삼지 않는다.

## 3. 제품 원칙

1. **시작이 쉽다.** 설치에 필요한 조건과 연결 실패 이유를 명확히 안내한다.
2. **일을 끝낼 수 있다.** 지원하는 업무는 대상 확인부터 실행·결과 확인까지 연결한다.
3. **결과를 믿을 수 있다.** 접수·진행·성공·실패·확인 불가를 구분한다.
4. **현재 상태에 근거한다.** 관찰 출처·시점·누락을 표시하고 실행 직전에 필요한 조건을 다시 확인한다.
5. **웹에서 업무를 끝낸다.** 웹은 서버 권한과 검증된 실행 경로를 사용한다. 별도 사용자 CLI·TUI와 에이전트 인증 구현은 현재 범위에 넣지 않는다.

## 4. 기본 구성과 완료 경험

아래는 제품 목표다. 제공 여부는 로드맵과 현재 아키텍처에서 구분한다. 첫 버전은 웹에서 기본 업무를 완료하는 범위이며, macOS·Linux 전체 조합이나 모든 인프라 설정의 동시 지원을 뜻하지 않는다. 첫 지원 환경과 세부 기능 범위는 로드맵·해당 작업에서 정한다.

| 영역 | 사용자가 끝낼 수 있어야 하는 일 | 완료를 판단하는 기준 |
|---|---|---|
| 설치·연결 | macOS·Linux에서 시작하고 Proxmox 연결 | 지원 환경·의존성을 안내하고 연결 상태와 권한 부족 원인을 확인 |
| 템플릿 | 기존 템플릿 등록·조회, 제작·준비·검증 | VM 배포에 필요한 조건의 충족·실패·확인 불가를 표시 |
| VM 관리 | 생성·복제·삭제·전원·사양·디스크·네트워크 관리 | 대상과 변경을 확인하고 실행 후 실제 상태 또는 미확정 사유를 표시 |
| 콘솔 | VM의 화면이나 지원하는 콘솔에 접속 | 갈랴르에서 인증된 세션으로 접근하고 종료 가능 |
| 모니터링 | 노드·VM·스토리지 상태와 사용량·추이 확인 | 마지막 관찰 시점·데이터 누락·실패한 작업을 구분하고 대상 관리로 연결 |
| 백업·복구 | 백업 확인·실행·VM 복원 | 지원하는 복구 단계와 결과 검증, 남은 확인 항목을 표시 |
| 인프라 | 일상 업무에 필요한 노드·스토리지·네트워크 관리 | 지원하는 변경의 영향과 실행 결과를 확인 |
| 웹 | 자원과 작업 관리 | 권한·작업 ID·진행 상태·결과 확인 |

템플릿은 OS·소프트웨어·기본 설정이며 사양 프리셋은 CPU·메모리 등 기본값·제약이다. 새 템플릿 버전으로 기존 VM이 자동 업데이트되지는 않는다. VM 실행 상태와 애플리케이션 정상 상태, 가상 디스크 확장과 게스트 파일시스템 확장은 각각 구분한다.

### 설치·접속 경험 (`APPROVED`, 부분 구현)

2026-09-25 사용자 결정으로 사용자 CLI·TUI를 제거한다. VM 관리·Proxmox 연결·모니터링은 웹에서 수행한다. 기존 설치를 유지하는 bootstrap·서비스·동일 schema 이미지 전환 명령만 남긴다.

2026-09-25 사용자 승인으로 웹 연결은 전체 조회·새 자원 자동 발견을 기본으로 한다. 노드·VM·스토리지·브리지 ID를 등록하는 입력은 없애고 생성·전원·삭제 등 허용 작업만 선택한다. 아무 작업도 선택하지 않으면 조회만 허용하며 신규 발급과 기존 token import 모두 이 방식을 지원한다. 기존 제한 연결은 표준 전환 전까지 보존한다.

시작 방식은 **이 컴퓨터에서 Gjallar 실행** 또는 **기존 Gjallar 서버에 연결** 두 가지다. 로컬 실행은 bootstrap이 서비스·DB 준비와 최초 계정 설정을 안내하고, 기존 서버 연결은 Gjallar 주소와 Gjallar 계정으로 접속한다. 별도 VM은 필수가 아니며 로컬에서도 Gjallar 서비스가 실행돼야 한다. 브라우저 종료와 서비스 종료를 구분한다.

웹은 접속한 Gjallar 서버의 API를 사용한다. 별도 Proxmox 직접 연결 운영 모드는 제공하지 않는다. Proxmox 토큰과 작업 기록은 Gjallar 서버가 관리하며 기존 서버에 접속하는 클라이언트에 Proxmox 토큰을 배포하지 않는다.

관리형 bootstrap과 아래 Proxmox 연결 핵심 흐름을 구현했다. 관리형 연결은 조회와 기능별 선택 권한을 제공하며 현재 지원 범위는 아래 구현 상태와 아키텍처를 따른다. 사용자는 2026-09-18 실제 Proxmox 연결 성공을 확인했다. 지원 OS·PVE 버전/인증 조합 전체와 운영 복구까지 검증한 것은 아니며 남은 항목은 [기능 로드맵](roadmap.md)에서 별도로 관리한다.

새 Proxmox 연결은 로그인 → 사용할 기능·대상·필요 권한 안내와 확인 → 전용 토큰 발급·권한 설정 → 안전한 저장 → 토큰으로 첫 자원 조회 순서다. Proxmox 로그인 비밀번호는 저장하지 않는다. 실제 부여 가능한 권한을 검사하며 로그인 성공만으로 발급·권한 설정 성공을 가정하지 않는다. 제품 로그인과 Proxmox 최초 연결은 별개다. 상세 인증·저장·실패 처리 계약은 아키텍처를 따르며, 기능별 권한과 지원 환경은 해당 작업에서 정하고 검증한다.

### 웹 사용 경험 (`APPROVED`)

2026-09-20 사용자 승인에 따라 대시보드를 포함한 웹 UI를 전면 개선한다. 상단은 전체 현황·VM 관리·템플릿·모니터링·인프라·작업 이력의 여섯 영역으로 나눈다. 공식 이미지 템플릿 제작·정리는 독립 메뉴로 제공하고, Proxmox 연결·스토리지·브리지 설정·노드 유지보수는 인프라에 모은다. 내 계정·사용자·세션 관리는 우측 계정 메뉴에서 접근한다. 모바일에서도 메뉴 이름과 현재 위치를 확인할 수 있어야 한다. canonical URL·권한·동의·실행 결과 계약을 보존한다. 실제 화면을 먼저 확인해 중복 메뉴·흩어진 작업·과도하게 노출된 정보를 식별한다. VM 관련 작업은 VM 상세에서 이어가고, 평소에는 현재 상태·결과·다음 조치를 우선 표시하며 상세 실행 기록·진단 정보는 필요할 때 확인하게 한다. 실행에 필요한 영향·경고·동의는 숨기지 않는다.

2026-09-20 추가 요청에 따라 정보 밀도가 높은 모니터링 화면을 지향한다. 전체 현황은 `클러스터 전체 / 노드 상세`로 나눈다. 클러스터 화면은 모든 연결 노드의 CPU·메모리·네트워크 집계와 작은 요약 행·노드 비교표·운영 확인 사항·최근 작업을 배치한다. 개별 노드의 자원 구성·추이·시각별 값·임계 이력은 노드 상세에서 확인한다. 공통 헤더·폼·목록의 여백을 줄인다. 수치·단위·상태를 먼저 읽게 하되 모바일 터치 영역과 경고·동의는 유지한다. CPU는 0~100% 축, 메모리는 확인된 용량을 반영하고, 현재 값과 마지막 이력값·결측·오래된 관찰을 구분한다.

정확한 메뉴·화면 구성은 현행 UI 검토 후 결정한다. 공통 탐색과 VM 상세 구조를 먼저 정하고 각 기능 구현과 함께 화면을 완성한다. UI 전체를 별도 선행 프로젝트로 만들거나 서버/API만 끝내고 화면 연결을 무기한 미루지 않는다. VM 콘솔도 웹에서 접속한다.

## 5. 현재 출발점

웹 기반 inventory와 VM 상세, Insights, 기존 템플릿 복제 기반 생성, 시작·정상 종료, 외부 실행 방식 Guided `qm unlock`, Operation 이력·검증·복구 관찰과 로컬 계정이 있다.

관리형 bootstrap과 최소 서비스 관리 명령을 제공한다. 사용자 CLI/TUI 인증·조회·VM 작업은 제거했다. 정지 VM의 CPU·메모리·NFS scsi0 확장·기존 NIC bridge/VLAN·full clone·명시적 삭제와 인증된 웹 콘솔은 코드로 구현했으며 실제 PVE 변경 검증은 남아 있다. 준비된 정지 VM의 템플릿 전환은 코드로 구현했으며 실환경 검증은 남아 있다. 공식 cloud image 제작과 소유 template/업로드 원본의 명시적 정리는 구현·격리 검증했으며 기존 생성 기반 테스트 배포 검사·운영자 접속 기록·명시적 테스트 VM 정리 동선을 연결했다. 실제 PVE 제작/배포/정리 검증은 남아 있다. 노드·VM·storage의 현재 지표/PVE 평균 추이·임계 초과/해제와 기존 작업 실패/복구 이력은 웹으로 구현했으며 관리형 설치 환경 검증은 남아 있다. 정지 VM의 NFS 백업 조회·명시적 생성은 웹으로 구현했으며 실제 생성 검증은 남아 있다. 별도 VMID 격리 복원과 원본/백업 보존·현재 부팅/agent 검사 보고서는 웹으로 구현했으며 실제 PVE 복원/부팅 검증은 남아 있다. 같은 클러스터·shared NFS의 정지 VM 수동 노드 이동은 웹으로 구현했으며 실제 PVE 이동·부팅 검증은 남아 있다. 노드 영향 자원과 VM별 백업·정지 이동 준비 보고서를 웹으로 구현했으며 연결 범위 밖 자원과 호스트 종료 안전성은 별도로 확인한다. 기존 directory storage 등록·content/사용 여부 변경과 선택 node 활성 확인은 관리자 웹으로 구현했으며 실제 PVE 검증은 남아 있다. VM용 Linux bridge의 생성·자동 시작/VLAN 변경·노드 전체 반영과 단계별 결과 확인도 관리자 웹으로 구현했으며 실제 PVE 반영 검증은 남아 있다. 구현 세부사항은 [아키텍처](architecture.md)에 한 번만 기록한다.

2026-09-19의 첫 실환경 검증은 PVE 9.0.11의 기존 token을 관리형 연결로 가져와 VM 7001의 정상 종료, 웹 CPU·메모리 변경, CLI 원복과 재시작까지 확인했다. 나머지 VM/템플릿/백업/호스트 기능 및 신규 PVE 로그인·token 발급은 아직 실환경 검증 완료가 아니다.

## 6. 우선순위와 범위 제한

기능 선택 기준은 **“어떤 업무 때문에 사용자가 갈랴르를 떠나 Proxmox를 여는가?”**다. 2026-09-18 사용자가 정한 우선 목표는 기본 운영 기능을 빠르게 완성해 실제로 사용하는 것이다. 2026-09-25부터 첫 버전은 **웹**에서 업무를 끝낸다. 사용자 CLI·TUI를 제거하고 서버/API와 필요한 웹 화면을 기능별로 함께 완성한다. 설치·기동·업데이트·복구에 필요한 최소 운영 명령만 유지한다. [기본 기능 로드맵](roadmap.md)은 설치·연결, VM 일상 관리, 템플릿, 모니터링, 백업·복구, 유지보수의 M1~M6로 구성한다. VM 일상 관리부터 사용을 시작하고 나머지를 추가하며 구현·인터페이스·실환경 검증 상태는 별도로 기록한다. 로드맵의 제한된 첫 지원 범위와 OPS-03 포함은 2026-09-19 사용자가 승인했다. 기능별 고위험 설계는 실행 전에 현재 work에 구체화하고, live 실행·설치·운영 DB 적용은 별도 승인한다. 과거 work의 M 번호와 완료 상태는 소급 변경하지 않는다.

초기에는 모든 Proxmox 설정의 동시 구현, 자체 하이퍼바이저·백업 엔진·범용 TSDB 제작, multi-provider, 임의 shell/SSH 실행, 무승인 자동 복구를 추진하지 않는다. DRS의 자동 배치·재균형 기능은 복원하지 않는다. 사용자 주도 정지 VM 이동은 현재 work의 제한된 지원·권한·복구 계약을 따른다.

AI는 이후 관찰 근거 수집·작업 실패 설명·계획 제안에 활용할 수 있다. 운영 권한과 실행 검증을 모델의 판단으로 대체하지 않는다. 모든 기본 기능의 완성을 기다려야 한다는 뜻은 아니지만, 해당 업무의 관찰·실행 계약이 먼저 필요하다.

## 7. 확인할 제품 성과

첫 사용 환경에서 다음을 측정한다. 아직 측정값이나 확정된 수치 목표는 없다.

- 설치 시작부터 실제 자원 확인까지 걸린 시간과 막힌 지점
- 선택한 일상 업무를 갈랴르 안에서 완료한 비율
- Proxmox 화면으로 이동한 이유와 빈도
- 작업 결과·실패 원인·다음 조치를 파악하는 데 걸린 시간
- 미확정 결과를 성공으로 잘못 표시한 사례

## 8. 유지할 안전성과 계약

Proxmox actual state, 서버 측 권한 검사, 승인 대상과 계획의 결합, 중복 실행 방지, target lock, 기록 보존과 결과 검증을 유지한다. 미확정 변경은 무작정 재실행하지 않는다. API·DB·복구 의미와 live 작업 경계는 기존 상세 문서를 따른다.

이 PRD는 이전의 제한된 실행 목록을 장기 제품 범위로 삼던 방향을 대체한다. 이전 명세와 결정 원문은 [보관본](archive/README.md)에 남기고 유지할 결정은 [아키텍처](architecture.md)에 통합한다. 새 기능을 이미 구현했거나 live 작업을 승인했다는 뜻은 아니다.
