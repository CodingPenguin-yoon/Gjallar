# ADR-009: Proxmox 현재 상태 기준과 Create 이력 저장의 분리

> 후속 구체화(2026-09-14): [ADR-012](adr-012-create-preset-and-history-retention.md)가 선택적 DB 프리셋 유지와 현재 저장 단위의 입력·검토·승인·작업 기록에 자동 만료·삭제를 도입하지 않는 정책을 확정한다. 아래는 결정 당시 기록이다.

- 상태: `ACCEPTED`
- 날짜: `2026-09-07`
- 결정자: `사용자`
- 관계: [ADR-008](adr-008-template-based-create-and-persistence-simplification.md)의 저장 의존성 단순화 방향을 구체화한다. 템플릿 기반 범위는 유지한다. [ADR-003](adr-003-production-inventory-connection-truth.md)의 연결 gate와 [ADR-004](adr-004-postgresql-durable-operation-recovery.md)의 coordination 원칙은 유지한다.
- 적용 상태: 제품·설계 원칙 합의. 계산·저장 분리 1단계가 구현됐으며 [구현 계획](../archive/plans/2026-09-07-template-create-state-and-history.md)은 승인된 1단계 범위에서 `IMPLEMENTED`다. 이후 [작업 직전 관찰](../archive/plans/2026-09-07-create-fresh-pre-dispatch-validation.md)과 [템플릿 직접 입력·선택적 프리셋](../archive/plans/2026-09-07-template-first-create-input.md)도 구현됐다. 이력 소유권·저장 구조 변경은 후속 설계다.

## 결정 배경

사용자는 이식성을 위해 DB 의존성을 줄이고 싶다고 설명한 뒤, 핵심 우려가 이력 저장 자체가 아니라 DB의 VM 상태와 Proxmox 실제 상태가 달라 발생하는 충돌임을 명확히 했다. 입력 이력도 보존할 수 있으며 실제 작업 직전에는 Proxmox를 조회하고 진행한다는 원칙에 동의했다.

따라서 “입력·검토를 전혀 저장하지 않는다” 또는 “생성 승인 시점부터만 기록한다”는 대화 중 제안은 최종 요구사항으로 채택하지 않는다. 저장량·테이블 수 최소화보다 현재 상태의 판단 권위와 역사 기록의 역할을 분리하는 것이 우선이다.

## 채택한 원칙

- 템플릿·VM·노드·스토리지·네트워크의 실제 정보는 Proxmox가 소유한다. Gjallar DB에 템플릿이나 VM을 먼저 등록해야 사용할 수 있는 목표 구조를 만들지 않는다.
- Proxmox 템플릿 선택 후 사양을 직접 입력할 수 있도록 한다. 프리셋은 선택적 편의 기능으로 두고, 기존 프로필의 기본값과 제한 정책을 구분하여 운영자 설정을 보존한다.
- 입력·검토·승인·실행·결과 이력은 DB에 보존할 수 있다. 관찰 기록은 대상·출처·관찰 시각을 갖는 당시 상태이며 현재 상태를 대체하지 않는다.
- 검토 계산은 DB 기록과 별도 책임이다. 기록을 남기는 application 단계가 계산 결과를 받아 저장하며, 계산 함수가 Jobs나 artifact를 직접 저장하지 않는 구조를 목표로 한다.
- 실제 mutation 직전에 Proxmox 상태를 새로 확인한다. 오래된 DB 상태나 검토 시점의 캐시만으로 실행 적격성을 판단하지 않는다. 조회 실패 시 실행하지 않는다.
- 승인한 대상·사양·위험 또는 실행 가능성에 영향을 주는 변화는 재검토를 요구한다. 과거 관찰값과 다르다는 이유만으로 충돌을 만들거나 원래 상태로 되돌리지 않는다.
- DB의 승인 binding, idempotency, 진행 중인 작업의 target lock, checkpoint와 recovery 근거는 실행 안전성을 위해 유지한다. 현재 VM 상태의 권위와 실행 조정의 권위는 서로 다르다.
- 직전 조회와 mutation 사이의 경쟁은 가능하다. 외부 API 오류·불명확한 결과를 처리하고, 실행 후 Proxmox의 task와 실제 상태를 검증한 뒤 결과를 기록한다. 자동 mutation 재시도로 해결하지 않는다.
- 비밀번호·토큰 등 시크릿은 입력 이력과 evidence에 저장하거나 노출하지 않는다.

## 선택과 남은 결정

| 선택 | 판단 |
|---|---|
| 입력·검토 이력을 일괄 제거 | 채택하지 않음. DB write 수 감소만으로 상태 불일치를 해결할 수 없음 |
| DB 상태를 현재 인프라 상태로 유지·동기화 | 채택하지 않음. 외부 변경과 복제 상태의 충돌·관리 부담 발생 |
| Proxmox 현재 상태 + DB 이력·실행 조정 | 채택. 실행 직전 조회 비용과 외부 연결 의존성을 감수 |

검토 버튼 시점에 이력을 남기는 방식을 구현 계획에서 제안한다. 저장 시점·보존 기간·저장 실패 시 검토 화면의 응답 정책은 아직 구현 승인 사항이 아니다. 인증·session의 DB 의존성, PostgreSQL 설치 방식, 장기 모니터링 저장소 변경도 이번 합의에 포함하지 않는다.

## 검증 기준

DB의 과거 관찰과 Proxmox 상태가 달라도 현재 조회가 반영돼야 한다. 승인 후 템플릿 삭제·VMID 선점·대상 조건 변경·조회 실패에서는 적절히 실행을 차단해야 한다. 동시에 동일 요청 replay·진행 중 작업 잠금·checkpoint 실패·재시작 복구를 보존해야 한다.
