## 결정과 변경

처음에는 폴더 재분류로 시작했으나 사용자가 문서 수 자체를 줄이기를 요청했다. 목표·현재·다음 일·운영 절차는 PRD·아키텍처·로드맵·개발 안내에서 관리한다. API·DB·도메인·실행 복구와 유효한 설계 결정은 아키텍처에 통합하고, 환경·검증은 개발 안내, 위험·승인은 AGENTS.md로 합쳤다. 계획과 결과는 같은 work 문서에 기록한다.

`project-docs`의 Markdown 63개를 8개로 줄였다. 과거 ADR·Plan·검증 원문과 미커밋 상세 문서는 압축 보관본 하나에 저장했다. 11개는 당시 Git HEAD에 동일 blob이 있고 나머지는 현재 작업 트리 원본도 보존해야 하므로 삭제 전 전체 묶음을 검증했다. 복원 절차는 [보관 안내](../archive/README.md)를 따른다. 로컬 Obsidian 설정은 계속 Git 제외 보관한다.

저장소 README는 영어 기본·한국어 링크를 유지한다. backend/frontend 안내는 중복 구현 설명을 제거하고 코드 위치·현재 문서 링크만 남겼다. 실행 기능·API·DB 의미는 변경하지 않았다.

## 마일스톤 구체화

기존 roadmap.md를 M1 설치·연결, M2 VM 일상 관리, M3 템플릿 관리, M4 모니터링, M5 백업·복구, M6 인프라 유지보수로 정리했다. 각 단계의 목표·포함/제외·선행 결정·완료 기준·상태를 명시하고 CLI는 M1 기반부터 단계별로 웹과 함께 확장한다. 신규 파일이나 구현 착수 없이 현재 문서 안에서 관리하며 모든 신규 마일스톤은 미착수다.

- 문서 계약 테스트 `test_legacy_backend_cleanup.py`: 10개 통과.
- 압축 원본 63개를 임시 디렉터리에 복원하고 manifest의 SHA-256과 전부 대조했다. 과거 live evidence 원문 6개 포함.
- 개발 안내의 모든 코드 블록이 통합 전과 동일함을 확인했다.
- README 양방향 언어 링크·명령 일치와 `git diff --check`를 확인했다.
- 문서만 변경했으므로 전체 `pnpm run verify`·container build·live Proxmox 검증은 수행하지 않았다.
