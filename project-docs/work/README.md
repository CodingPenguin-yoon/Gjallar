# 작업 기록

제품 전체 진행 상태는 [로드맵](../roadmap.md)에서 관리한다. 이곳에는 의미 있는 기능·문제 해결만 기록한다.

| 날짜 | 작업 | 범위 |
|---|---|---|
| 2026-09-16 | [제품 방향과 문서 정리](2026-09-16-documentation-foundation.md) | PRD 정립, 현재 계약 통합, 문서 수 축소. 실행 기능 변경 없음 |
| 2026-09-16~17 | [M1 설치·연결 조사와 설계](2026-09-16-m1-installation-connection.md) | M1-1 CLI/최소 TUI·M1-2 관리형 bootstrap 구현·격리 검증. 실제 설치와 후속 PVE credential 기능은 남음 |

큰 작업은 `YYYY-MM-DD-topic.md` 한 파일에 문제·목표·비범위·계획·검증 방법을 먼저 작성하고, 이후 실제 결과·검증·남은 일을 이어 기록한다. 검토·승인이 필요한 구현은 `DRAFT → APPROVED → IMPLEMENTED`로 구분한다. 별도 Plan과 완료 보고서를 중복 생성하지 않는다. 간단한 변경은 Git에 맡긴다.

작업 완료 시 아키텍처·개발 안내 등 바뀐 현재 문서와 로드맵을 갱신한다. 커밋·PR이 있으면 연결한다. 시크릿이나 민감한 원문 로그는 기록하지 않는다. [이전 작업 원본](../archive/README.md)은 역사이며 새 구현이나 live 실행의 승인이 아니다.
