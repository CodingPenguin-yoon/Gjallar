# Documentation Sync

Git 이력을 복제하지 않고 현재 프로젝트 지식만 실제 구현과 맞춘다.

## 준비

1. `.agent-harness/core/documentation.md`를 읽는다.
2. 사용자 요구사항, 최종 diff, 변경된 테스트와 설정을 확인한다.
3. 기존 `project-docs/`와 Project Profile의 기존 문서 지도를 검색한다.
4. 관련 템플릿은 새 문서가 실제로 필요한 경우에만 읽는다.

## 영향 판단

다음을 각각 확인한다.

- 프로젝트 목적, 범위, 요구사항
- 기술 스택, 버전, 실행 명령, 저장소 지도
- 아키텍처, 도메인, 데이터 소유권, 의존성
- 공개 API와 DB 계약
- 주요 성공·실패·데이터 흐름
- 기존 결정을 대체하는 새 아키텍처 결정

모두 바뀌지 않았다면 공동 문서를 수정하지 않고 종료한다. 코드 변경마다 Change 문서나 요약 파일을 만들지 않는다.

## 동기화

- Project Profile은 실제 선택과 실행 가능한 명령을 반영한다.
- Specification은 의도된 현재 요구사항을 반영한다.
- Architecture, Domain, Flow, API, Database 문서는 현재 구현을 반영한다.
- 기존 현재 상태 문서가 있으면 새 문서를 중복 생성하지 않고 갱신한다.
- 중요한 승인 결정만 새 ADR로 기록한다. 과거 ADR을 덮어쓰지 않는다.
- 고위험 Plan은 계획과 실제 구현의 차이, 검증 결과를 갱신한다.

문서에는 파일 경로와 주요 심볼을 사용하되 전체 소스코드와 불안정한 줄 번호를 복사하지 않는다.

## 개인 문서

사용자가 학습 자료나 상세 복습 문서를 요청하면 `.agent-local/`에 작성한다. 개인 문서를 Git에 포함하거나 공동 명세의 필수 근거로 만들지 않는다.

## 대조

1. 문서의 경로, 심볼, 명령이 실제로 존재하는지 확인한다.
2. 성공·실패·데이터 흐름이 코드와 일치하는지 확인한다.
3. `DRAFT`, `APPROVED`, ADR 상태가 승인 사실과 일치하는지 확인한다.
4. 구현하지 않은 기능과 실행하지 않은 검증을 완료로 기록하지 않는다.
5. 범위 밖 문서나 단순 문구를 불필요하게 수정하지 않는다.

## 결과 보고

- 생성하거나 갱신한 현재 상태 문서
- 문서에 반영한 핵심 계약과 결정
- 공동 문서 변경이 없으면 그 사실
- 여전히 확인되지 않은 문서·코드 차이
